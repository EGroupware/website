EGroupware Cloud- and Email-Services: Friday, 05.12.2025, 12:30 - 13.30 (CET):

Service interuption to EGroupware Cloud and mail services: our technical team has identified the following problem as the cause: A large customer experienced a fibre optic network outage. The customer has a permanent connection to our data centre for authentication against their ActiveDirectory. The timeout for establishing the connection was too high and ultimately caused an overload of requests to our management system and mail servers. By the time the system monitoring sent the alert, the system was already so overloaded that it took some time to fix the problem. In particular, the technical team first had to identify the cause and then take countermeasures. To prevent this from happening in the future, we will implement two measures over the next 1-2 weeks: Shorter timeouts prevent requests from building up and blocking the systems. According to monitoring, EGroupware and email were already accessible again from around 13:00 CET, but still with a higher load and therefore slower speeds. Since 13.30 CET, all systems have been available again and operating normally.

  • EGroupware: Implement different timeouts for connection establishment and responses when authenticating against external systems (ActiveDirectory, LDAP, OpenID Connect Provider).
  • Email: Implement different timeouts or implement a fix in a basic component for connection establishment and responses to the mail server.

Internal Server Error in Frankfurt: 01.06.2021 21:00 - 23.59 hrs

There was a problem in the EGroupware Cloud availability zone in Frankfurt from around 9pm, so that "500 Internal Server Error" occurred there again and again. The availability zone in Karlsruhe was not affected by the problem or only for a short time after we had switched everything to Karlsruhe as a workaround. Further investigations suggest that there is NO direct connection to the update to 21.1, but rather a problem with "Traefik" as a proxy / Kubenetes Ingress Controller, which only comes into play under very specific conditions. As a first step, we updated the version of "Traefik", which reduced the problem but did not eliminate it. A search in the "Github Forums of Traefik" gave a similar error description in the following post. In order to be able to provide a meaningfully usable EGroupware Cloud today, we removed "Traefik" and are talking directly to Nginx, so there were then no more "Internal Server Errors".
